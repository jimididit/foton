Limitations of this collection
  • Live collection. Running this tool altered the host: a process was created, files were written, event log entries were generated, and prefetch and AmCache were updated. No memory image and no disk image were produced.
  • Point-in-time volatile data. Process, connection, and session data reflect the moment of collection only. Activity that ended before collection is absent from those artifacts.
  • Log retention bounds the window. Event data is limited to the configured window and to what retention preserved. Where a log was cleared, everything before that point is unavailable from this host.
  • Heuristics are not detections. The pattern lists used here match on common attacker tradecraft and also match legitimate administrative tooling. Expect false positives, and treat an empty findings list as an absence of matched patterns, not an absence of compromise.
  • Signature status is not integrity. A valid signature does not mean the binary is benign, and an invalid one does not mean it is malicious. Catalog-signed system files frequently return non-Valid status.
  • No anti-rootkit capability. All data is gathered through the operating system's own APIs. Kernel-level tampering could render any of it unreliable.
  • Standard-user coverage. If this package was collected without Administrator rights, the Security log, Prefetch copies, Amcache, SRUM, VSS, secedit/auditpol, and other users' artifacts were skipped by design. See 00_Collection/collection_coverage.json. Do not read those gaps as a clean host.
  • Timestamps. All times are UTC as reported by this host. Verify the host clock against the time source data before building a timeline, and note that file MACB times are trivially modifiable.
